# 발표 요약: AI 고속차량 점검일지 자동 생성

> 점검 항목과 기준치는 공개 자료를 바탕으로 만든 시연용 예시다. 실제 정비 지침이 아니다.

## 문제

점검 결과를 종이에 적는다. 사무실에서 엑셀에 다시 입력한다. 사진을 정리하고 보고서를 따로 쓴다. 같은 내용을 여러 번 옮겨 적는 반복 업무가 점검 한 건마다 생긴다.

## Before / After (가정치)

계산식은 PROMPTS.md의 가정치를 그대로 쓴다. 실제 측정값이 아니다.

| 구분 | 계산 (가정) | 주간 시간 (가정) |
|---|---|---|
| Before | 건당 후처리 20분 (엑셀 재입력 10분 + 사진 정리 5분 + 보고 작성 5분) × 주 10건 (가정) | 200분 ≈ **3.3시간/주** |
| After | 확인·제출만 남아 건당 5분 (가정) × 주 10건 (가정) | 50분 ≈ **0.8시간/주** |

- 절감: (200 − 50) ÷ 200 = **약 75%** (가정)
- "주 10건"과 "건당 20분"은 가정이다. 실제 수치는 선배 점검자에게 확인한 뒤 바꾼다.

## 주요 기능

1. **체크리스트와 측정값 자동 판정**: 일상점검 23개, 월상점검 28개 항목. 측정값이 기준치를 벗어나면 자동으로 불량 처리된다.
2. **점검일지 엑셀·PDF**: 결과 화면 버튼을 눌러 내려받는다. 엑셀은 시트 2개, PDF는 A4 점검일지다.
3. **조치 요청 문구**: 긴급도 높은 순으로 정렬한다. 규칙 기반으로 즉시 만들고 복사 버튼을 제공한다.
4. **서버 저장과 팀 이력**: 로그인 후 점검 기록과 사진을 저장한다. 다른 기기에서 로그인해 같은 이력을 본다.
5. **정비 현황**: 지표 5개, 일자별·차종별·분야별·긴급도 차트, 반복 불량 상위 10, 편성별 현황을 보여준다.

## AI 활용과 한계

**1. 사진 판정 보조 (Claude)**
- 불량 항목에 사진을 올리면 Claude(Opus 5.5)가 "정상 / 찌그러짐 의심 / 판정불가"와 신뢰도, 근거 한 줄을 보여준다(배포 환경, 로그인 시).
- 한계: AI 판단은 참고용이며 사진 화질·각도에 따라 달라질 수 있다.
- "불량으로 표시" 버튼을 눌러야만 판정이 바뀐다. 최종 판정은 점검자가 한다.

**2. 조치 보고서와 분석 (Claude)**
- 점검 완료 시 불량 목록으로 조치 요청 보고서를 받는다.
- 이력 화면의 "반복 불량 분석", 정비 현황의 "AI 브리핑"으로 기간별 반복 불량·주의 편성·권고를 요약한다.
- 한계: 배포 환경에서만 동작한다. 원인은 추정으로만 표현한다. 실패하거나 20초를 넘기면 규칙 기반 문구가 그대로 남는다.

## 3분 시연 순서

1. 로그인
2. KTX-산천 월상점검 선택
3. 예시 데이터 채우기
4. 측정값이 기준치를 벗어나 자동 불량 처리되는지 확인
5. 사진을 올려 Claude AI 판정 확인 (참고용 표시)
6. 점검 완료
7. 결과 화면에서 엑셀·PDF 다운로드
8. AI 보고서 확인
9. 정비 현황에서 예시 이력 생성 후 지표·차트와 AI 브리핑 확인
10. 다른 브라우저에서 로그인해 이력 확인

## 향후 과제 (구현되지 않음)

- **권한 분리**: 현재는 로그인한 사용자 누구나 정비 현황을 볼 수 있다. 역할별 권한은 없다.
- **조치 완료 추적**: 즉시조치 건의 완료 여부를 기록하지 않는다. "미조치" 상태도 표시하지 않는다.
- **판정 정확도 검증**: 실제 점검 사진으로 AI 판정 정확도를 검증한다.
- **실제 기준치 반영**: 현재 항목과 기준치는 공개 자료 기반 시연용 예시다. 실제 정비 지침으로 검증하지 않았다.
